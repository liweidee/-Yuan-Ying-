## 零、先读这个：一条主线走完三个环境

Node / Python / PHP 的前半段**一模一样**，只有「装运行时 → 装依赖 → 启动命令」三处不同。先把这条主线背下来，后面三章直接跳到自己那门语言看差异就行：

```
装 PRoot 运行时  →  装 Alpine/Ubuntu  →  开文件访问权限
      ↓
项目放进 /storage/emulated/0/xxx/
      ↓
沙盒终端装运行时（node / python / php）
      ↓
服务卡「导入项目」→ 选目录 → 确认识别结果 → 创建服务
      ↓
终端里装依赖（npm / pip / composer）
      ↓
终端里手动跑一遍，浏览器验证通了
      ↓
点「启动」常驻  →  （可选）编辑勾自启动
```

> **三个最容易翻车的地方**（看完再去操作，能省一小时）：
> 1. **没开「所有文件访问」** → `/mnt/sdcard` 是空的，怎么都找不到项目
> 2. **监听地址写成 `127.0.0.1`** → 服务自己觉得跑起来了，手机/电脑死活打不开
> 3. **端口没填 / 填错** → 探活一直失败，15 秒后报超时

## 一、通用前置准备

### 1.1 步骤总览

| 步骤 | 动作 | 频次 |
| --- | --- | --- |
| ① | 装 **PRoot 运行时**（插件中心 → 市场 → Linux 沙盒运行时） | 一次性 |
| ② | 装 **Alpine / Ubuntu** 沙盒环境 | 一次性 |
| ③ | 授权 **「所有文件访问」** | 一次性 |
| ④ | 把项目放到 `/storage/emulated/0/xxx/` | 每个项目 |
| ⑤ | 终端里装运行时（`apk add nodejs` / `python3` / `php`） | 每个环境一次 |
| ⑥ | 服务卡 → **「导入项目」** → 选目录 | 每个项目 |
| ⑦ | 终端里装依赖 | 每个项目一次（装过就缓存着） |
| ⑧ | 点 **「启动」** → 看日志通过 | 每次跑 |

> 第 ① ② 步细节见《源影 Linux 沙盒使用指南》，本文聚焦「项目 → 服务」这一段。

### 1.2 授权「所有文件访问」

**为什么要做**：沙盒里看到的 `/mnt/sdcard` 其实是宿主存储的 bind 挂载，没授权时这个目录是**空的**，`ls` 什么都没有。

**操作路径**：

```
沙盒页顶部 → 「文件访问」按钮（盾牌图标）
  → 系统设置「所有文件访问权限」页
  → 打开「允许访问所有文件」
```

**验证**（进终端执行）：

```sh
ls /mnt/sdcard
# 正常能看到：Android  DCIM  Download  Music ... 等宿主存储根目录
```

### 1.3 把项目放到 sdcard

| 方式 | 操作 |
| --- | --- |
| 📱 数据线 | 电脑 → 手机存储根目录 → 新建 `my-project/` → 拖入全部文件 |
| 📂 MT 管理器 / 系统文件器 | 从别处复制到 `/storage/emulated/0/my-project/` |
| ☁️ 云端下载 | 浏览器下 zip → 解压到 `/storage/emulated/0/my-project/` |

> **⚠️ 命名铁律**：路径里**别带空格和中文**。`my-app`、`webapp`、`api_v2` 都行，`我的项目 2` 早晚出事。

### 1.4 sdcard 性能陷阱

`/storage/emulated/0` 走的是 **FUSE 文件系统**，小文件读写非常慢——而装依赖正好是「海量小文件」场景：

| 操作 | sdcard 上 | rootfs 内 | 差距 |
| --- | --- | --- | --- |
| `npm install`（中型项目） | 2–5 分钟 | 30–60 秒 | ≈4× |
| `pip install -r requirements` | 1–3 分钟 | 20–40 秒 | ≈3× |
| `composer install` | 1–2 分钟 | 20–30 秒 | ≈3× |

**解法**：**源码放 sdcard（方便在宿主改），依赖目录放 rootfs（跑得快）**。具体做法 → [6.2](#62-依赖目录放-rootfs性能优化)。

## 二、Node.js 完整指南

### 2.1 安装运行时

**Alpine**

```sh
apk update
apk add nodejs npm
node -v     # 预期：v22.x.x 或更高
npm -v      # 预期：10.x.x
```

**Ubuntu**

```sh
apt update
apt install -y nodejs npm
node -v
```

> **⚠️ Ubuntu 24.04 自带 Node 是 18.x**。要 Node 20+ 二选一：
> ```sh
> curl -fsSL https://deb.nodesource.com/setup_20.x | bash -
> apt install -y nodejs
> ```
> 或者干脆换 Alpine（默认就是 22）。

**验证**

```sh
node -e "console.log('OK:', process.version)"
# OK: v22.x.x
```

### 2.2 项目结构要求

Node 项目靠 **`package.json`** 被识别。最小结构：

```
my-node-app/
├── package.json          ← 必须有
├── app.js                ← 入口
└── node_modules/         ← 有就直接用，没有就装
```

**`package.json` 关键字段**

```json
{
  "name": "my-node-app",
  "version": "1.0.0",
  "main": "app.js",
  "scripts": {
    "start": "node app.js --port 5757"
  },
  "dependencies": {
    "express": "^4.18.2"
  }
}
```

**识别规则**（导入时的 `ProjectDetector` 逻辑）

| 项目 | 取值逻辑 |
| --- | --- |
| 入口文件 | ① `scripts.start` 里解析出的文件 → ② `main` 字段 → ③ 兜底猜 `app.js` / `index.js` / `server.js` / `main.js` |
| 端口 | 从 `scripts.start` 的 `--port 5757` 或 `config.port` 提取 |
| 装依赖命令 | 按 lock 文件选 `npm install` / `npm ci` / `yarn install` / `pnpm install` |

### 2.3 完整流程（Express 示例）

**Step 1 · 准备项目**

`app.js`：

```js
const express = require('express');
const app = express();
const PORT = process.env.PORT || 5757;

app.get('/', (req, res) => res.send('Hello from Node sandbox!'));
app.get('/api/health', (req, res) => res.json({ ok: true }));

app.listen(PORT, '0.0.0.0', () => {
  console.log(`Server listening on 0.0.0.0:${PORT}`);
});
```

`package.json`：

```json
{
  "name": "my-node-app",
  "version": "1.0.0",
  "main": "app.js",
  "scripts": { "start": "node app.js" },
  "dependencies": { "express": "^4.18.2" }
}
```

把俩文件放到 `/storage/emulated/0/my-node-app/`。

**Step 2 · 装运行时**（见 2.1）

**Step 3 · 导入项目**

```
服务卡 → 「导入项目」→ 选中 /storage/emulated/0/my-node-app
```

识别结果应类似：

```
识别结果：Node.js 项目
宿主目录    /storage/emulated/0/my-node-app
沙盒路径    /mnt/sdcard/my-node-app
入口文件    app.js
端口        5757
依赖安装    npm install
启动命令    cd /mnt/sdcard/my-node-app && node app.js
```

确认无误 → **创建服务**。

**Step 4 · 装依赖**

```sh
cd /mnt/sdcard/my-node-app
npm install
```

> `node_modules/` 会留在 sdcard 里，**装过一次就不用再装**。觉得慢就看 [6.2](#62-依赖目录放-rootfs性能优化)。

**Step 5 · 手动验证（关键！）**

```sh
node app.js
# Server listening on 0.0.0.0:5757
```

浏览器开 `http://手机局域网IP:5757`，看到 `Hello from Node sandbox!` 就算通了。
✅ 通了再点「结束」关会话，接下来交给服务常驻。

**Step 6 · 启动服务**

```
服务卡 → my-node-app → 「启动」
```

- 状态：`已停止 → 启动中 → 运行中`（15 秒内）
- 通知栏出现 **源影运行中 · 服务 1**
- 点「日志」能看到 `Server listening ...`

**Step 7 ·（可选）自启动**

```
服务卡 → 编辑 → 勾「自启动」→ 保存
```

之后 App 冷启动会自动拉起。

### 2.4 常见 Node 场景

| 场景 | 做法 |
| --- | --- |
| **A. 纯静态站**（html/css/assets） | `npm install -g http-server`，服务命令：`cd /mnt/sdcard/my-site && http-server -p 8080 -a 0.0.0.0` |
| **B. Vue / React 前端** | 先在沙盒里 `npm install && npm run build`，再用 `serve` 跑 dist：`cd /mnt/sdcard/my-vue-app/dist && serve -l 3000` |
| **C. Express 后端** | 项目里 `app.listen(port)` 直接跑，命令：`cd /mnt/sdcard/my-api && node server.js` |
| **D. 定时脚本** | `setInterval(()=>{...}, 60000)`，服务命令：`cd /mnt/sdcard/my-tasks && node tasks.js`，**端口留空**（探活走进程） |

### 2.5 Node 排障表

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `Cannot find module 'xxx'` | 没装依赖 / `cd` 错目录 | `npm install`，核对服务命令里的路径 |
| `EACCES: permission denied` | sdcard 没授权 | 回 [1.2](#12-授权所有文件访问) 开权限 |
| 启动 15 秒超时 | 没监听 / 绑了 `127.0.0.1` | 改成 `listen(port, '0.0.0.0')` |
| `EADDRINUSE` | 端口被占 | 换端口，或 `pkill -f node` |
| `npm install` 中途失败 | 网络 / 源慢 | 换淘宝源（[6.1](#61-加速依赖下载)） |
| 端口识别成 null | `package.json` 里没声明端口 | 服务表单里手动填 |

## 三、Python 完整指南

### 3.1 安装运行时

**Alpine**

```sh
apk update
apk add python3 py3-pip
python3 -V    # 预期：Python 3.12.x
pip3 -V       # 预期：pip 24.x
```

> **⚠️ Alpine 的 pip 默认拒绝全局装包**（PEP 668）。要么加 `--break-system-packages`，要么用 venv（[3.4](#34-推荐用-venv-隔离依赖)，更推荐）。

**Ubuntu**

```sh
apt update
apt install -y python3 python3-pip python3-venv
python3 -V
```

**验证**

```sh
python3 -c "import sys; print('OK:', sys.version)"
```

### 3.2 项目结构与识别规则

满足**任一条**就会被识别成 Python 项目：

| 标识 | 含义 |
| --- | --- |
| `requirements.txt` | 有依赖清单 |
| `pyproject.toml` | 现代打包项目 |
| `setup.py` | 老式打包项目 |
| `app.py` / `main.py` / `manage.py` 等 | 有入口文件 |

**入口文件识别顺序**

```
app.py → main.py → manage.py → wsgi.py → server.py → run.py
→ src/app.py → src/main.py
```

**框架特判**

| 发现 | 判定 | 默认启动命令 |
| --- | --- | --- |
| `manage.py` | Django | `python3 manage.py runserver 0.0.0.0:8000` |
| 其它 | 通用 | `python3 <入口文件>` |

### 3.3 完整流程（Flask 示例）

**Step 1 · 准备项目**

`app.py`：

```python
from flask import Flask, jsonify

app = Flask(__name__)

@app.route('/')
def index():
    return 'Hello from Flask sandbox!'

@app.route('/api/health')
def health():
    return jsonify(ok=True)

if __name__ == '__main__':
    app.run(host='0.0.0.0', port=8000)
```

`requirements.txt`：

```
Flask==3.0.0
```

放到 `/storage/emulated/0/my-flask-app/`。

**Step 2 · 装运行时**（见 3.1）

**Step 3 · 导入项目**

```
服务卡 → 「导入项目」→ 选 /storage/emulated/0/my-flask-app
```

```
识别结果：Python 项目
宿主目录    /storage/emulated/0/my-flask-app
沙盒路径    /mnt/sdcard/my-flask-app
入口文件    app.py
依赖安装    pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
启动命令    cd /mnt/sdcard/my-flask-app && python3 app.py
```

→ **创建服务**。

**Step 4 · 装依赖**

```sh
cd /mnt/sdcard/my-flask-app
pip3 install -r requirements.txt \
  --break-system-packages \
  -i https://pypi.tuna.tsinghua.edu.cn/simple
```

> 不加 `--break-system-packages` 会报 `error: externally-managed-environment`。用 venv 就不用这个参数了。

**Step 5 · 手动验证**

```sh
python3 app.py
# * Running on http://0.0.0.0:8000
```

浏览器开 `http://手机IP:8000` 验证。

**Step 6 · 注册 + 启动**

导入创建完直接点「启动」。**注意：Python 的端口识别不完整**，如果表单里端口是空的，去「编辑」手动填 `8000`。

### 3.4 推荐：用 venv 隔离依赖

比 `--break-system-packages` 干净，依赖放 rootfs 还更快。

```sh
# 创建 venv（放 rootfs，别放 sdcard）
python3 -m venv /opt/venv-flask

# 激活后再装依赖
source /opt/venv-flask/bin/activate
pip install -r /mnt/sdcard/my-flask-app/requirements.txt \
  -i https://pypi.tuna.tsinghua.edu.cn/simple

# 确认用的是 venv 的 python
which python    # /opt/venv-flask/bin/python
```

**服务命令要跟着改**（否则服务启动时还是系统 python）：

```sh
cd /mnt/sdcard/my-flask-app && /opt/venv-flask/bin/python app.py
```

### 3.5 常见 Python 场景

**A. Django**

```
my-django/
├── manage.py
├── requirements.txt
└── mydjango/
    └── settings.py
```

```sh
cd /mnt/sdcard/my-django
pip3 install -r requirements.txt --break-system-packages \
  -i https://pypi.tuna.tsinghua.edu.cn/simple
python3 manage.py migrate
# 服务命令（识别时自动生成，端口 8000）：
# cd /mnt/sdcard/my-django && python3 manage.py runserver 0.0.0.0:8000
```

**B. FastAPI（要 uvicorn + 可能要 Rust）**

```sh
pip3 install fastapi uvicorn --break-system-packages \
  -i https://pypi.tuna.tsinghua.edu.cn/simple
# 服务命令：
cd /mnt/sdcard/my-fastapi && uvicorn main:app --host 0.0.0.0 --port 8000
```

> **⚠️ FastAPI 的某些依赖需要 Rust 编译**。Alpine 上先 `apk add rust cargo`，否则 pip 会编不过；嫌麻烦直接用 Ubuntu（`apt install -y rustc cargo`）。

**C. 纯静态 HTTP**（零依赖，Python 自带）

```sh
cd /mnt/sdcard/my-site && python3 -m http.server 8080 --bind 0.0.0.0
```

**D. 定时脚本**

```python
# cron.py
import time, datetime
while True:
    print(datetime.datetime.now(), 'tick', flush=True)
    time.sleep(60)
```

服务命令：`cd /mnt/sdcard/my-cron && python3 -u cron.py`（**端口留空**，`-u` 强制无缓冲让日志实时刷出来）。

### 3.6 Python 排障表

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `error: externally-managed-environment` | PEP 668 保护 | 加 `--break-system-packages` 或改用 venv |
| `ModuleNotFoundError: No module named 'flask'` | 没装依赖 / 用了系统 python | 装包，或确认服务命令走的是 venv 的 python |
| pip 编译失败 | 缺系统编译工具 | Alpine：`apk add gcc musl-dev libffi-dev python3-dev`；Ubuntu：`apt install -y build-essential python3-dev libffi-dev` |
| FastAPI 装不上 | 缺 Rust | 换 Ubuntu，或 `apk add rust cargo` |
| `Address already in use` | 端口冲突 | 换端口 |
| 启动超时 | 只监听了 `127.0.0.1` | Flask/FastAPI 都写 `host='0.0.0.0'` |

## 四、PHP 完整指南

### 4.1 安装运行时

**Alpine**

```sh
apk update
apk add php php-cli php-openssl php-json php-curl php-phar php-mbstring
php -v     # 预期：PHP 8.3.x
```

> **💡 Alpine 的 PHP 是模块化设计**：基础包只带核心，扩展（`mbstring` / `curl` / `gd`…）要单独 `apk add php-xxx`。

**Ubuntu**

```sh
apt update
apt install -y php-cli php-curl php-mbstring php-xml php-json
php -v
```

**验证 + Composer（Laravel / Symfony 必备）**

```sh
php -r "echo 'OK: ', PHP_VERSION, PHP_EOL;"

# Alpine
apk add composer
# Ubuntu
apt install -y composer

composer -V
```

### 4.2 项目结构与识别规则

满足**任一条**即识别为 PHP 项目：

| 标识 | 判定 |
| --- | --- |
| `composer.json` | 现代 PHP 项目（Laravel / Symfony…） |
| `index.php` | 传统 PHP 站点 |
| `public/index.php` | 现代框架（文档根 = `public/`） |

**文档根识别**

| 项目结构 | 文档根 | 启动命令里的 `-t` |
| --- | --- | --- |
| 有 `public/index.php` | `public/` | `-t public`（Laravel 等） |
| 只有根目录 `index.php` | 项目根 | `-t .` |
| 都没有，但有 `.html` | 按静态站 | 改用 `busybox httpd` |

### 4.3 完整流程（原生 PHP 站点）

**Step 1 · 准备项目**

`/storage/emulated/0/my-php-site/index.php`：

```php
<?php
header('Content-Type: text/html; charset=utf-8');

if ($_SERVER['REQUEST_URI'] === '/api/health') {
    header('Content-Type: application/json');
    echo json_encode(['ok' => true]);
    exit;
}

echo "<h1>Hello from PHP sandbox!</h1>";
echo "<p>PHP " . PHP_VERSION . "</p>";
```

**Step 2 · 装运行时**（见 4.1）

**Step 3 · 导入项目**

```
服务卡 → 「导入项目」→ 选 /storage/emulated/0/my-php-site
```

```
识别结果：PHP 项目
宿主目录    /storage/emulated/0/my-php-site
沙盒路径    /mnt/sdcard/my-php-site
启动命令    php -S 0.0.0.0:8000 -t /mnt/sdcard/my-php-site
```

→ **创建服务**，**端口手动填 8000**。

**Step 4 · 手动验证**

```sh
cd /mnt/sdcard/my-php-site
php -S 0.0.0.0:8000
```

浏览器开 `http://手机IP:8000` → 看到 `Hello from PHP sandbox!`。

**Step 5 · 启动服务**

```
服务卡 → my-php-site → 「启动」
```

### 4.4 常见 PHP 场景

**A. 传统多文件站点**

```
my-site/
├── index.php
```

## 六、进阶技巧

### 6.1 加速依赖下载

**npm → 淘宝源**

```sh
npm config set registry https://registry.npmmirror.com

# 或者只在项目里生效，写 .npmrc：
echo "registry=https://registry.npmmirror.com" > /mnt/sdcard/my-app/.npmrc
```

**pip → 清华源**（导入识别时已经默认带上）

```sh
pip3 install -r requirements.txt \
  --break-system-packages \
  -i https://pypi.tuna.tsinghua.edu.cn/simple
```

**composer → 阿里云**

```sh
composer config -g repos.packagist composer https://mirrors.aliyun.com/composer/
```

### 6.2 依赖目录放 rootfs（性能优化）

**思路**：源码留 sdcard（宿主编辑器随手改），`node_modules` / `site-packages` / `vendor` 塞进 rootfs（ext4，小文件飞快）。

**Node.js**

```sh
mkdir -p /opt/my-app-deps
cd /mnt/sdcard/my-app
ln -sf /opt/my-app-deps/node_modules node_modules
npm install      # 实际写进 /opt/my-app-deps/node_modules
```

> 效果：`npm install` 提速 **3–5 倍**。

**Python（venv 天然就在 rootfs）**

```sh
python3 -m venv /opt/venv-flask
source /opt/venv-flask/bin/activate
pip install -r /mnt/sdcard/my-flask-app/requirements.txt \
  -i https://pypi.tuna.tsinghua.edu.cn/simple

# 服务命令：
cd /mnt/sdcard/my-flask-app && /opt/venv-flask/bin/python app.py
```

**PHP**

```sh
mkdir -p /opt/my-laravel-deps
cd /mnt/sdcard/my-laravel
ln -sf /opt/my-laravel-deps/vendor vendor
composer install
```

> **⚠️ 风险提示**：rootfs 里的东西**随「重装/卸载环境」一起没**。换环境或重装前，把 `package.json` / `requirements.txt` / `composer.json` 留好（它们在 sdcard，没事），重装后重新 `npm install` / `pip install` / `composer install` 即可复活。

### 6.3 环境变量注入

**方式一：命令里直接带（最省事）**

```sh
cd /mnt/sdcard/my-app && PORT=5757 NODE_ENV=production node app.js
```

**方式二：`.env` 文件（Node 示例）**

```sh
npm install dotenv
# app.js 第一行：
require('dotenv').config();
```

**方式三：写进 `.bashrc` 持久化**

```sh
echo 'export PATH=/opt/venv-flask/bin:$PATH' >> /root/.bashrc
```

> PHP 读 `.env` 靠框架自己解析（Laravel 自带）；Python 可用 `python-dotenv`。

### 6.4 日志实时性

| 语言 | 默认 | 要实时看到日志怎么做 |
| --- | --- | --- |
| **Node** | 行缓冲，基本实时 | `console.log` 直接出 |
| **Python** | 有缓冲，可能攒一批才刷 | 启动时加 `-u`：`python3 -u app.py` |
| **PHP** | `php -S` 一般实时 | 自己 `fwrite` 的话记得 `fflush()` |

### 6.5 多服务端口规划

| 用途 | 推荐端口 |
| --- | --- |
| Node 应用 | `3000` / `5757` / `8000` |
| Python Flask | `5000` / `8000` |
| Python Django | `8000` |

## 七、常见问题排查

### 7.1 通用排查四步法

```
① 服务启动失败        → 点「日志」，先看 stderr
② 日志是空的          → 点「结束会话」→ 终端里手动跑一遍那条命令
③ 手动能跑、服务不行   → 查 路径 / 端口 / 探活方式
④ 端口冲突            → 换端口，或查是不是宿主应用占着
```

### 7.2 分场景 FAQ

**Q1：`ls /mnt/sdcard` 是空的**
→ 没开「所有文件访问」。沙盒页顶部盾牌按钮 → 系统页开启（[1.2](#12-授权所有文件访问)）。

**Q2：`npm install` / `pip install` / `composer install` 慢得离谱**
→ 装在 sdcard 上了。按 [6.2](#62-依赖目录放-rootfs性能优化) 把依赖目录挪 rootfs。

**Q3：启动 15 秒超时**
手动跑一遍确认到底监听没：

```sh
cd /mnt/sdcard/my-app
node app.js                 # 或 python3 app.py / php -S 0.0.0.0:8000
```

| 语言 | 最常见死因 | 修法 |
| --- | --- | --- |
| Node | `listen(3000, '127.0.0.1')` | 改成 `'0.0.0.0'` |
| Python | Flask 默认只绑 `127.0.0.1` | `app.run(host='0.0.0.0')` |
| PHP | `-t` 路径错 / 端口错 | 核对命令 |

**Q4：状态「运行中」，浏览器打不开**
分段定位：

1. 手机浏览器开 `http://127.0.0.1:端口` → 应该能开（本机回环）
2. 电脑开 `http://手机局域网IP:端口` → 要和手机同 WiFi
3. 第 2 步不行 → 查路由器有没有开 **AP 隔离**

**Q5：端口冲突怎么查**

```sh
netstat -tlnp | grep 8000
# 或
lsof -i:8000
```

常见占用：`5575`（MediaProxy）、`8080`（系统/其它服务）、`3000`（另一个 Node）。
**解决**：改命令里的端口 → 编辑服务 → 保存 → 重启。

**Q6：服务崩了没自动拉起**
当前 `maxRestart = 1`，也就是**崩溃最多自动重启 1 次**，到上限就得手动点「启动」。
想调大只能改代码：`SandboxServiceManager._startInternal` 里的 `maxRestart`（比如改 5）。

**Q7：`Cannot find module 'xxx'` 但 `npm install` 明明成功了**
→ `cd` 的路径对不上。核对**服务命令里的 `cd`** 和你 `npm install` 时所在的目录是不是同一个。

**Q8：终端里按 `Ctrl+C` 没反应**
沙盒终端是**非 TTY**（`Process.start`，不是真 PTY），不支持信号快捷键。
**解决**：点「结束」按钮（先 `exit` 再 SIGKILL），或者 `pkill -f <进程名>`。

**Q9：想用 `vim` / `nano` 改文件**
不支持（无 TTY）。两条替代：
- 在宿主用 MT 管理器 / 文本编辑器直接改 sdcard 上的文件（改完沙盒里立刻生效）
- 沙盒里 `echo "content" > file.txt` 覆写

**Q10：App 重启后服务没自动起来**
依次查：
1. 「编辑」里有没有勾 **自启动**
2. 是不是从「最近任务」划掉过 App（那种情况系统会把服务一起杀掉，**下次冷启动**会重新拉起勾了自启的）
3. 电池优化有没有把源影设成「受限」→ 改成无限制
